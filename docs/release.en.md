# AWJ release procedure

## 1.1.0 release

The current `VERSION` is 1.1.0. See the [release notes](release-notes-1.1.0.md) and [validation record](validation-1.1.0.md). Final assets must come from the same clean source commit; review the signed manifest sequence, asset hashes, and public downloads.

1. Freeze a local candidate with **identical code content** on both platforms, then build Windows x64 Release and native Linux x64 Release and complete platform CTest, Studio/CLI smoke, and CPU baseline checks. Publication requires rebuilding from the same clean commit. Windows needs AVX2, Linux needs x86-64-v3; both Release builds require IPO/LTO. Do not build or package Linux under `/mnt`.
2. On a native Linux filesystem run `bash scripts/package-linux-release.sh --binary bin/x64/Release/AWJ --output-dir build/release-linux/1.1.0 --candidate-head <40-character-commit-SHA>`. The script requires a clean tree and verifies the exact `AWJ`, `LICENSE`, `NOTICE.txt` member set, archive integrity, extraction hashes, executable bit, and CLI. Copy the archive and three-file package into repository `build/` for Windows packaging.
3. With `pwsh7`, run `scripts/package-release.ps1 -WindowsExePath <AWJ.exe> -WindowsComPath <AWJ.com> -LinuxPackagePath <Linux-three-file-directory> -LinuxArchivePath <AWJ_Linux.7z> -Version 1.1.0 -SkipManifests`. It creates `build/release/1.1.0/assets/AWJ_Win.7z` and `AWJ_Linux.7z`, then checks exact members, integrity, extracted file hashes, and Windows CLI. The Windows archive contains exactly `AWJ.exe`, `AWJ.com`, `LICENSE`, `NOTICE.txt`; user configuration, presets, logs, test programs, and signing tools are excluded.
4. Record actual sizes and SHA-256 hashes for both archives and all members. Check `AWJimage 1.1.0`, the `NOTICE.txt` source commit, and matching Windows/Linux sources. Keep local validation evidence without mixing old candidates or user configuration into the packages.
5. For publication, rebuild both final assets from the reviewed clean tag, then use the external signing seed, valid keyring, and increasing sequence with `package-release.ps1` without `-SkipManifests`. Review complete assets, signatures, and hashes before publishing the GitHub Release. Verify public downloads before committing the signed manifest generated by **that packaging run**. Do not rerun packaging solely to sign; archive hashes could change. Run real updater end-to-end tests only on local Windows.
